# Отображение, поиск, фильтрация и сортировка данных

## Реализация задания

Задание реализовано на страницах `/medications/` и `/diary/`. Обработка выполняется
на сервере через Django ORM и GET-параметры. JavaScript для поиска не требуется.
После отправки формы параметры остаются в URL, поэтому выборку можно открыть повторно
или обновить страницу. Сохранённые записи при этом не изменяются.

| Часть задания | Реализация |
| --- | --- |
| Отображение | Карточки препаратов и таблица дневника, число результатов и сообщения о пустой выборке |
| Поиск | Подстрока в текстовых полях без учёта регистра, включая кириллицу |
| Фильтрация | Режим и статус курса; даты, самочувствие, настроение и диапазон боли |
| Сортировка | Название и даты курса; дата записи и интенсивность боли |
| Длинные списки | По 20 записей на странице с сохранением параметров при переходе |

## Страница препаратов

- `q`: поиск по названию, дозировке, назначению и примечанию к приёму.
- `section`: `all`, `courses`, `occasional`. Раздел по умолчанию берётся из сессии;
  значение в URL имеет приоритет. Прежние кнопки разделов сохраняют выбор через POST.
- `status`: пустое значение, `active`, `upcoming`, `finished`. Статус курса относится
  только к регулярным препаратам. Начало и конец активного курса включительны.
- `sort`: `name_asc`, `name_desc`, `start_desc`, `start_asc`, `end_asc`.
  Препараты без дат курса располагаются последними при сортировке по датам.
- `page`: номер страницы.

Все карточки составляют один упорядоченный список. Иначе деление на две группы
«Курсы / Без курса» нарушало бы общий порядок по названию. Режим и статус видны
в карточке. Переключение раздела сохраняет поиск и сортировку и возвращает первую
страницу. «Сбросить» показывает все препараты без поисковых условий.

Пример с искусственным поисковым текстом:

```text
/medications/?q=тест&section=courses&status=active&sort=name_asc
```

## Страница дневника

- `q`: поиск по симптомам и заметке.
- `date_from`, `date_to`: период в формате `YYYY-MM-DD`, обе границы включительны.
- `condition`, `mood`: значения из соответствующих полей модели.
- `pain_min`, `pain_max`: границы интенсивности боли от 0 до 10. Ноль является
  допустимым значением, а не признаком отсутствия фильтра.
- `sort`: `date_desc`, `date_asc`, `pain_desc`, `pain_asc`.
- `page`: номер страницы.

Условия действуют совместно. Например, можно найти записи с определённым симптомом
за период, оставить только оценки боли 3–7 и поставить сильную боль в начало списка.

## Где находится код

| Файл | Ответственность |
| --- | --- |
| `diary/filter_forms.py` | Допустимые GET-параметры, даты, границы боли и варианты сортировки |
| `diary/selectors.py` | `medications_for`, `health_entries_for`: ограничение владельцем, `filter`, `Q`, `order_by` |
| `diary/db_functions.py` | `UnicodeLower`: обработка регистра в SQLite и штатный LOWER других СУБД |
| `diary/apps.py` | Подключение Unicode-функции к каждому SQLite-соединению |
| `diary/views.py` | Проверка формы, вызов селектора и `Paginator.get_page` |
| `templates/components/list_filters.html` | Общая GET-форма с выбранными значениями и ошибками |
| `templates/components/pagination.html` | Переходы между страницами с `{% querystring %}` |
| `templates/medications/list.html`, `cards.html` | Отображение отобранных препаратов |
| `templates/diary/list.html` | Отображение отобранных записей дневника |
| `diary/tests/test_list_filters.py` | Проверки поиска, сочетаний, сортировки, страниц и доступа |
| `browser_tests/components.cjs` | Сценарии `medicationList` и `diaryList` на двух ширинах экрана |

Стандартный SQLite `LOWER` не приводит кириллицу к нижнему регистру, поэтому простого
`icontains` недостаточно для русского текста. Зарегистрированная функция использует
Unicode `str.lower`. Сравнение по подстроке остаётся ORM-выражением: пользовательский
текст передаётся параметром, а `%` и `_` экранируются как буквальные символы.

Сначала выборка ограничивается текущим пользователем. Параметр сортировки проверяет
`ChoiceField`, затем он выбирает заранее заданный набор SQL-полей из словаря.
Произвольная строка из URL в `order_by` не передаётся. К порядку добавлен `pk`, чтобы
одинаковые значения не перемещались случайно между страницами.

При ошибочной дате, перевёрнутом диапазоне или недопустимом варианте сортировки
показана ошибка и пустая выборка: условия не игнорируются молча. Стандартная
HTML-валидация дополнительно помогает при обычном вводе, но сервер повторяет проверки.

## Демонстрация задания

1. Создать несколько тестовых препаратов с разными названиями и параметрами курса.
2. В «Препаратах» найти препарат по части названия, сменив регистр букв.
3. Применить раздел и статус курса; переключить направление сортировки.
4. Открыть дневник, найти текст в симптомах или заметке, задать период и границы боли.
5. Отсортировать по интенсивности боли, затем по дате. Нажать «Сбросить».
6. Показать адресную строку: GET-параметры описывают текущую выборку.
7. На тестовых данных с более чем 20 совпадениями перейти на следующую страницу:
   поиск, фильтры и сортировка сохранятся.

Проверки: `venv\Scripts\python.exe scripts/check.py` и браузерный набор с `--browser`.
Данные для демонстрации и тестов должны быть искусственными; автоматические тесты
работают в отдельной базе.
