# Личный кабинет

После входа кабинет открывается по `/accounts/profile/` через пункт «Личный кабинет»
в меню «Профиль» в шапке. Там же находится кнопка выхода.

Форма данных расположена сразу после заголовка. Имя и дата регистрации показаны
компактной строкой, логин — в поле формы без повторной карточки аккаунта. Сводка
записей находится справа, а на узком экране — после формы. Смена пароля доступна
внизу блока профиля; выход не дублируется в содержимом кабинета.

## Возможности

- Просмотр логина, имени и даты регистрации.
- Изменение логина, имени, фамилии и необязательной электронной почты.
- Сводка: все препараты, активные курсы, записи самочувствия и отмеченные приёмы.
- Переход из показателей к соответствующим личным спискам.
- Просмотр даты последней записи дневника.
- Смена пароля отдельной стандартной формой Django и выход из аккаунта.

После изменения логина используется новый логин для последующих входов.
Текущая сессия сохраняется. Электронная почта не является способом входа;
подтверждение и восстановление пароля по почте не реализованы.

## Ответственность кода

| Файл | Назначение |
| --- | --- |
| `diary/forms.py`, `ProfileForm` | Разрешённые поля, проверки формата и уникальности логина |
| `diary/auth_views.py`, `profile_view` | Доступ после входа, форма только текущего пользователя, POST/redirect/GET |
| `diary/auth_views.py`, `ProfilePasswordChangeView` | Смена пароля Django и сообщение об успехе |
| `diary/selectors.py`, `account_summary_for` | Счётчики без загрузки всей истории и только по владельцу |
| `diary/urls.py` | Маршрут кабинета и стандартные маршруты аутентификации |
| `templates/account/profile.html` | Данные аккаунта, форма, сводка и действия |
| `templates/base.html` | Ссылка на кабинет для вошедшего пользователя |
| `static/css/profile.css` | Оформление кабинета на широком и узком экране |

Изменения используют стандартные поля модели пользователя Django. Новая таблица,
миграция или копия персональных данных не требуются. Приложение сохраняет данные
профиля в локальной БД, которая исключена из Git.

## Правила доступа

В URL нет идентификатора аккаунта: форма привязана исключительно к `request.user`.
Поля прав доступа, пароля и чужого владельца не входят в `ProfileForm` и игнорируются
при подстановке в POST. Пароль изменяется отдельной формой с проверкой старого пароля.
Отправка формы защищена CSRF. Логин проверяется на уникальность стандартным ModelForm.
Имя и фамилия выводятся с HTML-экранированием.

Невалидная форма не сохраняет частичные изменения. После ошибки поля содержат
введённые значения для исправления, а карточка аккаунта показывает сохранённые данные.
Статистика исключает чужие записи. Активный курс включает даты начала и окончания;
разовые препараты, завершённые и будущие курсы в число активных не входят.

## Проверка

```cmd
venv\Scripts\python.exe manage.py test diary.tests.test_profile diary.tests.test_auth
venv\Scripts\python.exe scripts/check.py --browser --browser-channel msedge
```

Браузерный сценарий `profile` проверяет переход из шапки, показатели, ошибку почты,
сохранение данных и смену логина без потери сессии на широком и мобильном экране.
Используются только искусственные тестовые аккаунты и отдельная БД.
