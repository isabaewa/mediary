# ЛЗ 12. Безопасность Mediary

Проверка выполнена на дневнике самочувствия, включая поиск через Fetch.

| Что проверено | Как Django защищает приложение | Как проверить |
| --- | --- | --- |
| Валидация | `HealthEntryForm` проверяется на сервере через `is_valid()` перед сохранением. | Отправить оценку боли 11 при выбранном «Есть боль». Форма покажет ошибку, запись не сохранится. |
| XSS | Шаблоны `diary/detail.html` и `diary/list_fragment.html` экранируют пользовательский текст. | Сохранить заметку `<img src=x onerror=alert(1)>`. На странице детали и в совпадении поиска это текст. |
| SQL Injection | Поиск передаёт введённую строку как значение фильтра Django ORM в `diary/selectors.py`. Поля сортировки выбираются из заданного в коде набора. | Поиск по `' OR 1=1 --` ищет буквальную строку. |
| CSRF | `CsrfViewMiddleware` проверяет токен. Форма подтверждения удаления содержит `{% csrf_token %}`. | POST без токена получает 403. GET показывает подтверждение, корректный POST удаляет запись. |
| Управление доступом | `@login_required` требует входа, а запросы к конкретной записи проверяют `owner=request.user`. | Открыть или попытаться удалить запись под другим аккаунтом по её ID. Сервер вернёт 404. |

В рамках ЛЗ добавлены явные ограничения HTTP-методов на маршруты дневника. Список и карточка принимают GET и HEAD, формы создания, редактирования и удаления также принимают POST. Для списка, в том числе ответа Fetch, и карточки записи добавлен `@never_cache`, чтобы HTTP-кэши не сохраняли ответы с личными данными.

Автоматическая проверка из корня проекта

```powershell
.\venv\Scripts\python.exe manage.py test diary
```
