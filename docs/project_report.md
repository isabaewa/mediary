# Краткое описание проекта СРС 1
**Проект: Mediary — дневник самочувствия и приёма лекарств**  
Дисциплина: «Разработка веб-приложений».

## Постановка задачи
Разработать личный дневник с базой данных для хранения препаратов, отметок приёма и самочувствия. Целевой пользователь — человек, которому нужно вести свои записи и просматривать историю.

## Реализация
Использован стек Python + Django + Django ORM + SQLite. Приложение `diary` содержит модели, формы, представления, маршруты и сервис расписания. Базовый шаблон обеспечивает общую шапку, навигацию и оформление.

Препараты поддерживают полный CRUD и режимы «Регулярно» и «Иногда». Приёмы связаны с препаратом через ForeignKey. Плановые приёмы учитываются в ежедневном прогрессе; дополнительные записи сохраняются отдельно с выбранной фактической датой, временем и необязательной причиной. Дневник самочувствия также поддерживает полный CRUD. Журнал показывает сегодняшние и прошлые записи.

## Работа через ORM
Создание выполняется через ModelForm.save() и QuerySet.create(); чтение — filter(), get() и select_related(); изменение — save() и update(); удаление — delete(). Миграции создают таблицы и ограничения. Согласование курса и связанные изменения выполняются внутри transaction.atomic().

## Проверка корректности
Проверяются обязательные поля, даты курса, диапазоны количества приёмов и боли, повторяющиеся времена, будущие фактические записи и уникальная дата дневника. Ограничения БД дополняют проверку форм. Выполненные записи сохраняются при редактировании расписания; удаление препарата требует подтверждения и удаляет его приёмы.

Автоматические тесты проверяют CRUD и ключевые бизнес-сценарии. Команды запуска и проверки приведены в README. Исходная пользовательская SQLite сохранена локально и не включена в публикуемые материалы.

## Ограничения текущей версии
Добавлены регистрация, вход, выход, смена пароля и персональные аккаунты через Django Authentication. Записи связаны с владельцем, все пользовательские запросы ограничены его данными. Session хранит вход и раздел препаратов; cookie запоминает настройку входа. Уведомления и восстановление пароля по почте не реализованы.

## Демонстрация
Назначение → схема БД → CRUD препарата → ошибка валидации → отметка приёма → дополнительная запись за прошлый день → CRUD дневника → основные файлы кода. Продолжительность 5–7 минут.
