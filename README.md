# Mediary — дневник самочувствия и приёма лекарств

СРС 1 по дисциплине «Разработка веб-приложений»

## Назначение
Личный дневник для записи самочувствия, хранения препаратов и учёта фактических приёмов. Приложение поддерживает отдельные личные аккаунты; оно не назначает лечение и не заменяет консультацию врача.

## Стек
Python, Django, Django ORM, SQLite, HTML, CSS, JavaScript. Точные версии зависимостей указаны в `requirements.txt`.

## Основные функции
1. Полный CRUD препаратов: создание, просмотр, изменение и удаление с подтверждением.
2. Два режима: «Регулярно» (курс и 1–12 приёмов в день) и «Иногда» (без дат курса и расписания). Время регулярных приёмов необязательно.
3. Отметка планового приёма и запись фактического времени. Неотмеченные приёмы после заданного времени или за прошедший день показываются как пропущенные.
4. Дополнительный приём: выбор сохранённого или добавление нового препарата, фактическая дата и время, необязательная причина. Можно записать за прошлый день; будущие значения запрещены. Дополнительные записи не меняют ежедневную цель.
5. Полный CRUD дневника: настроение, самочувствие, симптомы, боль 0–10 и заметка. При выборе «Нет боли» сохраняется 0.
6. Журнал сегодняшних и прошлых записей, история препарата по 20 строк, серверная валидация и ограничения целостности.

## База данных и структура
Схема: [docs/database_schema.svg](docs/database_schema.svg), описание: [docs/database_schema.md](docs/database_schema.md).

- `Medication` — препарат, режим, назначение, дозировка и параметры курса.
- `MedicationIntake` — отдельный приём, связанный с препаратом отношением один ко многим.
- `HealthEntry` — самостоятельная запись самочувствия, одна на дату.

`diary/models.py` задаёт модели и ограничения; `forms.py` проверяет ввод; `views.py` обрабатывает запросы; `services.py` согласует расписание. Маршруты находятся в `diary/urls.py`, страницы наследуют `templates/base.html`. Изменения схемы хранятся в `diary/migrations`.

Оформление хранится в `static/css`: `style.css` содержит общие стили, `utilities.css` — повторно используемые классы, остальные CSS-файлы — стили отдельных страниц. Базовый шаблон подключает общие файлы через `{% static %}`, а страницы добавляют свои через блок `extra_css`. JavaScript переключает классы и значения элементов; CSS в шаблонах не используется.

При редактировании расписания выполненная история сохраняется. После окончания курса он исключается из главной цели. Даты курса включительны. Удаление препарата каскадно удаляет его приёмы; перед удалением показано подтверждение.

Поведение интерфейса разделено на компоненты в `static/js`, подключаемые через `extra_js`. Поля препарата и дневника вынесены в отдельные включаемые шаблоны. Карта файлов, контракты обработчиков и результаты проверки структуры: [docs/architecture.md](docs/architecture.md).

## Запуск в Windows CMD
Установите Python 3.12 или совместимую версию с зависимостями проекта. Откройте CMD в распакованной папке:

```cmd
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe manage.py migrate
venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000/. Остановка — Ctrl+C. SQLite создаётся командой `migrate`; отдельный сервер БД не нужен. База с личными записями и виртуальное окружение не включены в архив и Git.

Для уже настроенного проекта достаточно:

```cmd
venv\Scripts\python.exe manage.py runserver
```

## Настройки
Часовой пояс: `Asia/Yekaterinburg` (UTC+5). Дата и фактическое время приёма отображаются в нём. Для другого часового пояса измените `TIME_ZONE` в `config/settings.py`.

Для постоянного ключа сессий задайте переменную окружения `DJANGO_SECRET_KEY`. Без неё используется постоянный случайный ключ из локального файла .django_secret_key, исключённого из Git. Секреты не хранятся в репозитории. `DEBUG=True` предназначен для локальной демонстрации; проект не подготовлен к публичному размещению.

Реализованы регистрация, вход, выход, смена пароля и доступ только к своим данным. Уведомления и восстановление пароля по почте не реализованы. Django Admin доступен после `manage.py createsuperuser`, но не нужен для основных функций.

## Проверки
```cmd
venv\Scripts\python.exe manage.py check
venv\Scripts\python.exe manage.py makemigrations --check --dry-run
venv\Scripts\python.exe manage.py test diary
```
Тесты выполняются в отдельной базе. Покрыты CRUD, ошибки ввода, ограничения, сохранение истории, режимы препаратов, пропуски, дополнительные приёмы, прошедшие даты, причины и постраничная история.

Для разработки добавлены Ruff, отдельные браузерные тесты и общий запуск проверок
через `venv\Scripts\python.exe scripts/check.py`. Подготовка окружения и команды
описаны в [docs/development.md](docs/development.md).

## Демонстрация: 5–7 минут
1. Назначение приложения и схема БД.
2. Добавить тестовый регулярный препарат на сегодняшний день, открыть и изменить его.
3. Показать ошибку: окончание курса раньше начала.
4. Отметить приём и показать фактическое время.
5. Добавить препарат «Иногда», записать дополнительный приём за вчера с причиной; показать журнал.
6. Создать, открыть, изменить и удалить тестовую запись самочувствия; удалить тестовый препарат с подтверждением.
7. Кратко объяснить роли модели, формы, представления, маршрута и базового шаблона.

## Session и Cookies
Выбор раздела хранится в request.session. Вход сохраняется сессионной cookie sessionid; «Запомнить меня» продлевает сессию на 14 дней. Собственная cookie mediary_remember сохраняет предпочтение флажка на 30 дней. Реализация и сценарий демонстрации: [docs/session_cookies.md](docs/session_cookies.md).


## Регистрация и вход
Первое открытие сайта перенаправляет на /accounts/login/. Новый пользователь регистрируется через ссылку «Зарегистрироваться». Пароли проверяются средствами Django и сохраняются хешированными. В меню есть «Сменить пароль» и «Выйти».

Для развёртывания новой копии выполнить migrate и зарегистрировать свой аккаунт; локальные пароли и ключи не включены в исходники. Обновление существующей базы описано в [docs/authentication.md](docs/authentication.md). Учебные задания оформлены отдельно: [регистрация и доступ](docs/authentication.md), [Session и Cookies](docs/session_cookies.md).
